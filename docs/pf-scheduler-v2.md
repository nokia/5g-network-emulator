# Proportional-Fair Scheduler V2

## Configuration

PF is selected with:

```ini
[MACLayer]
metric_type: 6
pf_alpha: 1.0
pf_time_window_ms: 100.0
pf_intra_tti_update: none
```

`pf_alpha` is cell-wide. Per-UE weighting is configured separately through
`priority`.

The legacy per-UE `beta_metric` key is rejected when `metric_type: 6` is
selected. It remains available to scheduler policies that use the BET
parameter.

## Metric

\[
M_{i,b}(t)=
\frac{w_i\,r_{i,b}(t)^\alpha}
{\max(\bar R_i(t),\epsilon)}
\]

- \(w_i\): UE priority.
- \(r_{i,b}\): achievable rate on allocation unit \(b\), refreshed with CQI.
- \(\alpha\): cell-level rate/fairness exponent.
- \(\bar R_i\): EWMA of effective served payload.

## TTI state update

\[
\bar R_i(t+1)=
(1-a)\bar R_i(t)+a\,x_i(t),
\qquad
a=1-e^{-1\,\mathrm{ms}/\tau}
\]

- The update runs exactly once after every 1 ms MAC step.
- \(x_i(t)\) is effective payload served after packet/HARQ handling.
- Active, backlogged, valid-MCS UEs that receive no service contribute zero.
- UEs with no backlog freeze their state.
- Detaching a UE resets its PF state.
- A newly active UE initializes its state from its current standalone
  achievable rate.

CQI reporting controls the achievable-rate numerator only; it does not control
the service-history update.

## Tie handling

Exact metric ties use a persistent round-robin cursor local to each allocation
unit. UE container order must not determine long-run allocation.

## Intra-TTI allocation

`pf_intra_tti_update` accepts:

- `none`: no provisional service update within the TTI;
- `allocation_unit`: update the winner's provisional current-TTI service
  after every scheduled RB/RBG and rerank subsequent units.

Both modes commit the EWMA exactly once at TTI end using effective payload.
The experimental mode uses nominal scheduled bits only for provisional
intra-TTI ordering. It must be benchmarked across localized/distributed and
grouped/per-RB scheduling modes before a production default is selected.

## Migration

Remove `beta_metric` from every PF UE section and add the two PF keys to
`[MACLayer]`.

Before:

```ini
[UE]
beta_metric: 0.01

[MACLayer]
metric_type: 6
```

After:

```ini
[UE]
priority: 1

[MACLayer]
metric_type: 6
pf_alpha: 1.0
pf_time_window_ms: 100.0
pf_intra_tti_update: none
```

Historical results generated by the legacy PF algorithm should be associated
with their original Git commit. V2 intentionally provides no runtime legacy
mode.
